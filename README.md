# AI-Based Military Intelligence Dashboard

AI-assisted Streamlit multipage dashboard for exploratory analysis of the **Global Terrorism Database (GTD)**, including interactive geospatial analysis, country-level analysis, attack-type prediction, threat-level assessment, forecasting, AI-assisted intelligence summaries, and data exploration.

## Setup

Install the required Python packages:

```bash
pip install -r requirements.txt
```

The Global Terrorism Database (GTD) CSV is not included in this repository.

### 1. Add the GTD Dataset

Place the GTD CSV file at:

```text
data/globalterrorism.csv
```

### 2. Train the Attack Prediction Model

If the trained model artifacts are not already present, run:

```bash
python train_attack_model.py
```

This creates the `models/` directory containing:

* `attack_prediction_model.pkl`
* `feature_encoders.pkl`
* `target_encoder.pkl`

### 3. Run the Application

Start the Streamlit dashboard with:

```bash
streamlit run app.py
```

### Optional PyDeck Support

The Global Threat Map supports **PyDeck** as an optional WebGL-based renderer.

If PyDeck is installed, the map can use a WebGL `ScatterplotLayer`. If PyDeck is unavailable, the application automatically falls back to Plotly.

To install PyDeck separately:

```bash
pip install pydeck
```

## Dashboard Modules

The application is organized as a nine-page Streamlit dashboard:

1. **Home** — dashboard overview, KPIs, and navigation.
2. **Global Threat Map** — interactive geographical visualization of terrorism incidents.
3. **Country Analysis** — country-level incident analysis and trends.
4. **Attack Prediction** — Random Forest-based attack-type prediction.
5. **Threat Level** — threat-level classification and assessment.
6. **Forecasting** — historical trend analysis and future incident forecasting.
7. **AI Intelligence** — automated intelligence summaries and analytical insights.
8. **Data Explorer** — filtering, exploration, and downloading of GTD records.
9. **Settings** — application settings and dataset validation.

## Data Loading and Caching

The application uses a shared data-loading function so that the different dashboard pages operate on the same dataset-loading pipeline.

The GTD CSV is loaded using Pandas and cached using Streamlit's:

```python
@st.cache_data
```

Missing values for selected casualty fields are handled during data loading.

This reduces repeated file-loading operations during normal dashboard interaction.

## Global Threat Map

The Global Threat Map is designed to handle the large number of GTD records while maintaining interactive performance.

### Automatic Downsampling

The map defines a display limit of:

```text
DOWNSAMPLE_LIMIT = 20,000
```

When automatic downsampling is enabled and the filtered dataset exceeds this limit, a subset of records is displayed for interactive visualization.

The user can also choose to view the full filtered map.

**This 20,000-record limit applies to the Global Threat Map visualization. It does not reduce the underlying GTD dataset used by the analytical or machine-learning components.**

### PyDeck WebGL Rendering

The map optionally supports PyDeck's WebGL rendering through a:

```text
ScatterplotLayer
```

This provides an alternative rendering path for large collections of geographic points.

### Plotly Fallback

When PyDeck is unavailable or not selected, the application uses Plotly's geographic visualization:

```python
px.scatter_geo(...)
```

This maintains compatibility without requiring PyDeck.

### Reduced Visualization Payload

The map limits unnecessary hover information in the Plotly visualization to reduce the amount of data serialized and transferred to the browser.

## Data Explorer

The Data Explorer provides controlled access to the GTD records.

Available display options include:

* **100 rows**
* **1,000 rows**
* **5,000 rows**
* **All rows**

The Data Explorer does **not** use the Global Threat Map's 20,000-record downsampling mechanism.

When the user attempts to display more than **10,000 rows**, an additional confirmation is required.

The application also provides a full filtered-data download as a **gzipped CSV**, reducing the size of the downloadable payload.

These safeguards help prevent unnecessarily large Streamlit/browser payloads when working with the full dataset.

## Machine Learning

The project contains two classification components and one forecasting component.

### Attack-Type Prediction

The Attack Prediction page uses a **Random Forest classifier** to predict the recorded attack type from selected GTD attributes.

The model uses the following features:

* Country
* Region
* Weapon type
* Target type
* Perpetrator group
* Success indicator
* Suicide indicator
* Number killed
* Number wounded

The supplied implementation uses the cleaned dataset and an 80/20 train-test split.

### Threat-Level Assessment

The Threat Level page uses a Random Forest classification model.

The current implementation derives threat categories from casualty-related information. Because the casualty fields are also available as model inputs, the resulting evaluation contains **target leakage**.

Therefore, the near-perfect score produced by the shipped implementation should **not** be interpreted as genuine independent predictive performance.

The project report documents this limitation and includes an independently evaluated context-only formulation without the leaked casualty inputs.

### Forecasting

The Forecasting page uses **Linear Regression** to estimate future annual incident counts for a selected country based on its historical annual incident series.

The forecasting component is intended for exploratory trend analysis rather than high-confidence real-world prediction.

## Performance and Application Improvements

The project includes several improvements for usability, performance, and maintainability.

### Data and Application Improvements

* Centralized data loading through the shared loader.
* Added `@st.cache_data` for dataset loading.
* Improved handling of missing or unavailable model artifacts.
* Improved dataset validation in the Settings page.
* Standardized Streamlit page filenames and sidebar ordering.
* Added shared application state and global filters.
* Added reusable UI components and centralized styling.

### Attack Prediction Improvements

* Prediction runs after explicit form submission rather than on every interaction.
* Trained model artifacts are stored separately from the source code.
* Model artifacts are compressed using Joblib.

### Threat-Level Improvements

* Threat-level model loading is cached to reduce unnecessary retraining during interaction.

### Visualization Improvements

* Global Threat Map supports 20,000-record automatic display downsampling.
* Optional PyDeck WebGL rendering is available.
* Plotly remains available as the fallback geospatial renderer.
* Large hover payloads have been reduced.
* Data Explorer provides controlled row display and compressed full-data downloads.

## Model Evaluation

The verified project results include:

### Attack-Type Classifier

* **Top-1 Accuracy:** 86.37%
* **Top-3 Accuracy:** 98.49%
* **Macro F1:** 0.674
* **Weighted F1:** 0.858

The attack-type classifier was evaluated using **164,817 cleaned records**, with 20% reserved for testing.

### Threat-Level Classifier

The shipped threat-level implementation produces approximately:

* **99.99% Accuracy**

However, this result is **leakage-driven** because casualty variables used to construct the threat target are also supplied to the classifier.

An independently evaluated context-only formulation produced:

* **69.53% Accuracy**
* **0.459 Macro F1**

This corrected result is included to demonstrate the effect of the target leakage and should be interpreted as a methodological evaluation rather than a deployed replacement model.

### Forecasting

For the India example, the Linear Regression forecasting model achieved approximately:

* **R² = 0.63**

The forecasting result represents an exploratory trend model based on historical annual incident counts.
